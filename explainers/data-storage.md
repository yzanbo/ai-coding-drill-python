# どこに何を保存しているか（エンジニアじゃない人向け）

このサイトは、ユーザーの情報・問題・解答・採点結果などの **いろいろなデータ** を扱います。
それらを **どこに・どういう理由で** しまっているかを、
**絵と例え話だけ** で、まずはざっくり説明します。

> ℹ️ いまデータの保管場所は **2 つ** です（Postgres と Redis）。
> 「S3」という保管場所の名前を聞いたことがあるかもしれませんが、
> このサイトでは **今はまだ使っていません**（将来の選択肢。最後に少し触れます）。

---

## いちばん大事な考え方：保管場所を「目的」で使い分ける

データには性質の違いがあります。

- **ずっと残しておきたいもの**（ユーザー情報、解いた問題の履歴など）
- **一時的でよいもの**（ログイン状態、計算結果の使い回しなど）

この 2 種類を **同じ場所に混ぜず、目的に合った保管場所に分けて** しまいます。

例えるなら、

- **ずっと残す書類は「書庫」に整理して保管**（＝ Postgres）
- **その日だけ必要なメモは「付箋」に書いて貼る**（＝ Redis。期限が来たら自然にはがれて消える）

ようなものです。混ぜないことで、探しやすく・壊れにくく・速くなります。

---

## 登場人物（2 つの保管場所）

```
  Postgres                         Redis
  (書庫 / ずっと保管)               (付箋 / 一時的・自動で消える)
   📚                               🗒️
```

| 保管場所 | 例え名 | 性質 | 何のために使う |
|---|---|---|---|
| **Postgres**（RDS） | 書庫 | **ずっと残す**。きっちり整理された棚 | サイトの本体データ（ユーザー・問題・解答・採点結果など）（→ [ADR 0037](../docs/adr/0037-sqlalchemy-alembic-for-database.md)） |
| **Redis**（Upstash） | 付箋 | **一時的**。期限が来ると自動で消える。出し入れがとても速い | ログイン状態・一時トークン・計算結果の使い回し・回数制限（→ [ADR 0047](../docs/adr/0047-session-store-on-redis.md)、[ADR 0005](../docs/adr/0005-redis-not-for-job-queue.md)） |

> 🤔 なぜ 2 つに分けるの？
> 「ずっと残すデータ」は、多少遅くても **絶対に失われないこと** が大事です（書庫）。
> 「ログイン状態」のような一時データは、**とにかく速く出し入れできること** と
> **期限が来たら勝手に消えてくれること** が大事です（付箋）。
> 求められる性質が逆なので、得意分野の違う 2 つに役割分担させています。

## 何がどこに入っているか

### 📚 Postgres（書庫）— ずっと残すもの

サイトの「本体」となるデータです。消えては困るものばかりなので、きっちり保管します。

| しまうもの | 中身のイメージ |
|---|---|
| ユーザー | 誰がこのサイトを使っているか（GitHub ログインの情報と結びつく） |
| 問題 | AI が作って検証に通った、出題できる練習問題 |
| 解答 | ユーザーが送ったプログラムの中身 |
| 採点結果 | その解答が何点だったか・どのテストに通ったか |
| やることリスト（ジョブ） | 「この解答を採点して」「この問題を作って」という作業依頼。**待ち行列も Postgres が兼ねる**（→ [ADR 0004](../docs/adr/0004-postgres-as-job-queue.md)） |
| 生成リクエスト | 「こういう問題が欲しい」という依頼と、その進み具合 |

> 🔒 解答コードのような中身はここに保存されますが、**ログ（動作記録）には残しません**。
> 学習のための大切なデータと、運用のための記録は、扱いを分けています。

### 🗒️ Redis（付箋）— 一時的なもの

速さと「自動で消えること」が活きる、短命なデータです。

| しまうもの | なぜ Redis か | いつ消える |
|---|---|---|
| ログイン状態（セッション） | 毎リクエストで確認するので、速く読めることが重要 | 7 日（最終アクセスから延長） |
| ログイン途中の合言葉（state トークン） | なりすまし防止用の使い捨て。短時間だけ要る | 約 10 分（1 回使ったら破棄） |
| AI の計算結果の使い回し（キャッシュ） | 同じ依頼に毎回 AI を呼ぶと遅く・高くつくため | 一定期間（例：7 日） |
| 操作回数のカウント（レート制限） | 「1 分に何回まで」を高速に数えるため | 短時間ごとにリセット |

> ⏰ Redis の便利な点は、**保存するときに「賞味期限」を一緒に決められる**こと。
> 期限が来たら自動で消えるので、古いデータの掃除を自分でやらなくて済みます。
> （ログイン状態が「7 日で切れる」のはこの仕組みです）

## S3 について（今は使っていない）

「画像やファイルは S3 に置くのでは？」と思うかもしれませんが、
このサイトは今のところ **画像やアップロードファイルを扱っていない** ため、
**S3（大きなファイル向けの保管場所）は使っていません**。

将来、もし大量の動作記録（ログ）を安く貯めておきたくなったら、
そのときに S3 を保管場所として使う案はあります（→ [ADR 0041](../docs/adr/0041-observability-stack-grafana-and-sentry.md)）。
あくまで **将来の選択肢** で、現時点では出番がありません。

## まとめ

```
   ┌────────────────────────────────────────────────┐
   │ データは「目的」で保管場所を使い分ける             │
   │                                                │
   │  📚 Postgres（書庫）                            │
   │     ずっと残すもの：ユーザー・問題・解答・採点結果   │
   │     ＋「やることリスト（ジョブ）」も兼ねる         │
   │                                                │
   │  🗒️ Redis（付箋）                               │
   │     一時的なもの：ログイン状態・合言葉・           │
   │     計算結果の使い回し・操作回数。期限で自動消去    │
   │                                                │
   │  S3 は今は未使用（将来ログ保管に使うかも）         │
   └────────────────────────────────────────────────┘
```

「ずっと残す＝書庫（Postgres）」「一時的＝付箋（Redis）」という役割分担さえ掴めば、
このサイトがどこに何をしまっているかは、だいたい見通せます。

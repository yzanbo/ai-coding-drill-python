# 「生成中…」「採点中…」の待ち方（ポーリング）（エンジニアじゃない人向け）

問題を作るとき、答えを採点するとき、画面には少しの間「生成中…」「採点中…」と表示されます。
このとき裏で何が起きているのか、そして
**途中でページを離れて戻ってきても続きから見られるのはなぜか** を、
**絵と例え話だけ** で、まずはざっくり説明します。

> ℹ️ この流れは **今ちゃんと動いています**。
> 「ポーリング」という耳慣れない言葉が出てきますが、
> 中身は「ブラウザが定期的に『もう終わった？』と聞きに行くこと」だけです。

---

## いちばん大事な考え方：進み具合の「本当の状態」はサーバが持っている

問題作りや採点は **数秒〜数十秒** かかります。その間、

- 実際の作業をしているのは **サーバの裏方（Worker）**
- あなたの **ブラウザは作業をしていません**。ただ「終わった？」と聞きに行くだけ

そして、いま何段階目まで進んだか・終わったか・失敗したかという
**「本当の状態」は、すべてサーバ側（Postgres）に記録** されています。

ここがいちばん大事です。**ブラウザは状態を持っていません**。
だから、ブラウザを閉じても・別ページに行っても、**作業は止まらず裏で進み続けます**。
戻ってきたときは、サーバに記録された「今の状態」を読み直すだけ——だから続きから見えるのです。

例えるなら、**クリーニング店に服を預ける** のと同じです。

- 預けたあと、あなたは店の前で待つ必要はありません（外出してOK）
- 仕上がりの進み具合は **店（サーバ）が管理** しています
- あなたは時々「もうできましたか？」と聞きに行くだけ（＝ポーリング）
- 預かり票（URL）を持って戻れば、いつでも今の状況を確認できます

---

## 登場人物

```
 ブラウザ          サーバ                    裏方の職人
 (あなた)          (受付 + 状態の記録)        (Worker)
   👤              🏪 + 📚                   🧑‍🍳
 「終わった?」      今の状態を答える            実際に作る/採点する
 と聞きに行く                                （ブラウザとは無関係に進む）
```

| 登場人物 | 役割 |
|---|---|
| **ブラウザ（あなた）** | 「終わった？」と定期的に聞きに行く（ポーリングする側） |
| **サーバ（受付＋記録）** | 聞かれたら「まだ」「○段階目」「完了」「失敗」と、記録されている今の状態を答える |
| **裏方の職人（Worker）** | 実際に問題を作る・採点する。ブラウザが開いていようが閉じていようが進める |

---

## ポーリングってなに？

ポーリング＝**ブラウザが一定間隔で「もう終わった？」と繰り返し聞きに行くこと**です。

```
ブラウザ「終わった?」→ サーバ「まだ（生成中）」     ← 1秒後
ブラウザ「終わった?」→ サーバ「まだ（検証中）」     ← また1秒後
ブラウザ「終わった?」→ サーバ「まだ（品質チェック中）」← また1秒後
ブラウザ「終わった?」→ サーバ「完了！結果はこれ」   ← 完了を検知して表示
```

終わるまでこれを繰り返し、**終わったら聞くのをやめます**（無駄な問い合わせを止める）。

---

## ① 問題生成のポーリング

問題作りには段階があります。サーバは今どの段階かを記録していて、ブラウザはそれを取りに行って **進み具合のインジケータ** を出します。

```
🤖 AI が作成中  →  🧪 模範解答を検証中  →  🧐 品質をチェック中  →  💾 保存中  →  ✅ 完了
(llm_generating)  (sandbox_verifying)    (judging)            (persisting)
```

- **完了したら**：作られた問題のページへ **自動で移動** します
- **失敗したら**（最大 3 回作り直してもダメ）：「生成に失敗しました」と表示し、**「再試行」ボタン** を出します

## ② 解答採点のポーリング

採点も同じ仕組みです。「実行」ボタンを押すと、ブラウザは **1〜2 秒ごと** に結果を聞きに行きます。

```
ブラウザ「採点終わった?」→ サーバ「まだ（採点中）」
ブラウザ「採点終わった?」→ サーバ「終わった！5問中5問正解」→ 結果を表示
```

採点が終わった状態（`graded`）になった瞬間に、画面が「採点中…」から結果表示に切り替わります。

## ページを離れて、戻ってきたら？（重要）

ここが今回いちばん伝えたいところです。

**問題生成中に別のページに行ったり、ブラウザを閉じたり、しばらくしてから戻ってきても大丈夫です。**

理由は冒頭の考え方どおり——**作っているのは裏方の職人（Worker）で、進み具合はサーバが記録している** からです。ブラウザを閉じても職人は手を止めません。

### 戻ってきたときに起きること

戻ってきたブラウザは、サーバに「今どうなってる？」と聞き直すだけです。サーバの記録に応じて、こう分岐します：

```
        ┌──────────────────────────────────────┐
戻ってきた │ サーバに「今の状態」を聞く                │
        └──────────────────────────────────────┘
                          │
        ┌─────────────────┼─────────────────┐
        ▼                 ▼                 ▼
  まだ生成中           もう完成してた        失敗してた
  (pending)           (completed)         (failed)
        │                 │                 │
        ▼                 ▼                 ▼
  「生成中…」の          作られた問題の        「失敗しました」＋
  続きを表示し、         ページへ自動で移動    「再試行」ボタンを表示
  またポーリング再開
```

つまり、**離れている間に進んだぶんは、戻った瞬間にちゃんと反映** されます。
「生成中に離脱 → 戻ったらまだ生成中」なら、何事もなかったように **続きから「生成中…」** が表示され、ポーリングが再開します。

### 戻る道は 2 つ

| 戻り方 | どうなるか |
|---|---|
| **生成中ページの URL に戻る**（`/problems/generate/:requestId`） | 預かり票（requestId）を使って、その生成の今の状態を直接確認できる |
| **生成履歴ページを開く**（`/me/generations`） | URL を忘れても大丈夫。自分の生成リクエスト一覧が出て、進行中のものはリアルタイムに状態が更新される。クリックすれば生成中ページに入れる |

> 📝 補足：MVP では生成の **キャンセル機能はありません**。
> 一度始めた生成は、ページを閉じても裏で最後まで（成功 or 失敗まで）進みます。
> 採点結果も保存されるので、後から見直しても同じ結果が返ります。

---

## タブを裏に回している間は、そっと止まる

ずっと聞き続けるのは無駄なので、**ブラウザのタブが裏に隠れている間はポーリングを一時停止** します。
そしてタブを **表に戻すと自動で再開** します。

これも「本当の状態はサーバが持っている」から安心してできることです。止めている間に進んだぶんは、タブを戻したときにまとめて反映されます。

## まとめ

```
   ┌────────────────────────────────────────────────┐
   │ 進み具合の「本当の状態」はサーバが持っている         │
   │                                                │
   │  作業するのは裏方の職人（Worker）                 │
   │  ブラウザは「終わった?」と聞きに行くだけ（ポーリング）│
   │                                                │
   │  だからページを離れても作業は止まらない            │
   │  戻ってきたら「今の状態」を読み直すだけ            │
   │   ・まだ → 続きから「生成中…」                    │
   │   ・完成 → 問題ページへ自動で移動                 │
   │   ・失敗 → 「再試行」ボタン                       │
   │                                                │
   │  URL を忘れても生成履歴ページから辿れる            │
   │  タブを裏にすると一時停止、戻すと再開              │
   └────────────────────────────────────────────────┘
```

ポーリングは「ブラウザが定期的に聞きに行くだけ」のシンプルな仕組みです。
そして **状態をサーバ側に持たせている** おかげで、離脱・再訪・タブ切り替えに強い、
壊れにくい待ち方になっています。
